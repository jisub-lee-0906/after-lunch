# 영양채움 점심 라벨 known caveats

목적: 현재 `식단 밀도`, `식단 요약`, `bridge comment`가 충분히 운영 가능한 수준에 도달했지만, 과적합을 피하기 위해 아직 전역 규칙으로 강제 보정하지 않은 예외와 운영 중 계속 관찰해야 할 포인트를 정리한다.

## 현재 결론

- 현재 라벨링은 whole-tray score 기반으로 동작한다.
- 초등학교 실데이터 40건 spot-check, 고진중학교 집중 점검, 인접 중학교 95건 확대 검증까지 거쳤다.
- 반복적으로 드러난 과소평가 패턴은 대부분 보강했다.
- 지금 남은 caveat는 “명확한 반복 버그”라기보다 “운영 중 관찰이 필요한 잔여 예외”에 가깝다.

---

## 1. calorie-only outlier는 즉시 전역 보정하지 않는다

대표 사례:
- 서현중학교 20260413
- 메뉴: `찹쌀밥 / 어묵국 / 유자단무지맛살냉채 / 고구마맛탕 / 열무김치 / 마들렌`
- 현재 라벨: `균형 잡힌 구성 / 담백한 편`
- recorded calories: `1190`

왜 바로 고치지 않았는가:
- 칼로리 수치만 높고, 강한 메인/튀김/묵직한 단백질 신호는 약하다.
- 이런 사례를 잡겠다고 calorie threshold를 전역 상향하면 일반적인 급식까지 과도하게 거칠게 라벨링될 위험이 있다.

운영 원칙:
- 같은 유형이 반복적으로 누적되기 전까지는 known caveat로 유지한다.
- 비슷한 사례가 여러 학교/여러 날짜에서 반복될 때만 calorie weighting 재검토를 한다.

## 2. 메뉴명 coverage 부족은 architecture가 아니라 keyword 보강으로 대응한다

이번 검증에서 실제로 보강된 패턴:
- `오리훈제`
- `삼겹살편육`
- `수육`
- `편육`
- `함박`
- `삼겹살고추장구이`
- `오리쌈`
- `마파두부`
- `순대곱창볶음`
- `오향장육`
- `장육`
- `유린기`

운영 원칙:
- 새로운 이상 사례가 보이면 먼저 해당 메인 메뉴명이 `heavyKeywords`, `greasyMainKeywords`, `friedKeywords`, `proteinMainKeywords`, `primaryProteinKeywords`에 충분히 반영돼 있는지 확인한다.
- 반복 패턴이 명확할 때만 coverage를 추가한다.
- 한 학교의 1회성 표현만으로 전역 규칙을 크게 바꾸지 않는다.

## 3. copy tone 이슈는 scoring 이슈와 분리해서 본다

이미 조정한 사례:
- `기름진 편` → `기름기 있는 편`
- `점심이 조금 무거웠어서...` → `점심이 조금 진한 편이어서...`

운영 원칙:
- 라벨이 맞는데 문구만 거칠게 느껴지면 scoring을 다시 건드리지 않는다.
- parent-facing tone 문제는 bridge comment / label string 수준에서 최소 수정한다.
- 문구 변경 시에는 런타임 회귀 테스트와 실제 모바일 UI 시각 QA를 함께 다시 본다.

---

## 4. `담백한 편` 잔존 케이스는 우선 tray-level 근거부터 본다

점검 질문:
1. 메인 단백질이 분명히 묵직한가?
2. 튀김/기름진 조리 신호가 있는가?
3. 국/후식이 calories만 올린 것은 아닌가?
4. 부모가 식판 전체를 봤을 때 정말 `담백한 편`으로 읽히지 않는가?

운영 원칙:
- 단순히 calories가 높다는 이유만으로 `담백한 편`을 제거하지 않는다.
- 실제 tray impression과 반복성 둘 다 확인되면 그때 규칙을 보강한다.

---

## 5. 운영 중 추가 수집하면 좋은 사례 형식

이상 사례를 남길 때 아래 형식을 권장한다.

- 학교명
- 날짜
- 원본 점심 메뉴 전체
- calories
- 현재 `densityLabel`
- 현재 `summaryLabel`
- 현재 `bridgeComment`
- top3 추천 메뉴
- 왜 어색한지 한 줄 메모

좋은 예시 메모:
- "칼로리는 높지만 실제로는 후식 비중이 커서 지금 라벨 유지가 맞는지 애매함"
- "삼겹살 계열 메인인데 담백한 편으로 내려가 부모 관점에서 약해 보임"
- "문구는 맞지만 표현이 다소 직설적으로 느껴짐"

---

## 6. 현재 운영 판단

- known caveat가 존재한다고 해서 지금 라벨링이 배포 불가 상태는 아니다.
- 현재 남은 caveat는 전역 retune보다 운영 관찰이 더 적절한 수준이다.
- 다음 우선순위는 규칙 재설계가 아니라 운영 환경 점검, 실서비스 smoke test, 이상 사례 수집 루프 정리다.
